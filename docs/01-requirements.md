# 01. 요구사항

## 1. 개요
| 항목     | 값                                                                 |
| ------ | ----------------------------------------------------------------- |
| 한 줄 정의 | 팀마다 보드를 하나씩 두고, 팀원별 진행 부하를 한눈에 보며 협업하는 칸반 보드                      |
| 목적     | 팀 내부 도구 (가정)                                                      |
| 디바이스   | 데스크톱 우선, 모바일은 열람 시 깨지지 않는 수준 (가정)                                 |
| 스택     | React + TypeScript + Vite, 드래그 앤 드롭은 @dnd-kit (가정), 백엔드는 Supabase |
| 저장     | Supabase Postgres                                                 |
| 인증     | Supabase Auth 이메일 로그인 (이메일 + 비밀번호 방식은 가정)                         |
| 접근 정책  | RLS 활성화. 모든 테이블에 anon 역할도 읽기·쓰기 가능한 전체 허용 정책 적용                   |
| 시간 예산  | 반나절2                                                              |

## 2. 주 사용자와 사용 상황
- 누구: 3~8명 규모 팀의 팀장 또는 팀원. 한 사람이 여러 팀에 속할 수 있음
- 얼마나 자주: 매일 여러 번. 스탠드업 때, 작업을 시작하거나 끝낼 때
- 언제·어디서: 각자 업무용 데스크톱 브라우저에서 같은 보드를 열어 사용
- 다른 상황: 팀장이 주 1회 팀원별 업무량을 점검하며 일을 다시 나눔

## 3. 핵심 문제
어떤 일이 어느 단계에 있는지는 일반 칸반으로도 보인다. 하지만 **누가 일을 너무 많이 들고 있는지**는 카드를 하나씩 세어봐야 알 수 있어서, 업무 쏠림을 늦게 발견한다.

## 4. 핵심 기능 (MVP)
1. 이메일로 가입하고 로그인·로그아웃. 로그인하지 않으면 보드 화면에 들어갈 수 없음
2. 팀 생성, 이름 변경, 삭제, 상단에서 팀 전환 (팀 1개 = 보드 1개)
3. 팀원 등록 (이름만 받고 이니셜 아바타 자동 생성)
4. 컬럼 추가, 이름 변경, 순서 변경, 삭제. 기본 컬럼은 할 일 / 진행 중 / 완료
5. 카드 생성, 편집, 삭제. 드래그로 컬럼 간 이동과 순서 변경. 변경 내용은 바로 Supabase에 저장
6. 카드에 담당자 지정 (1명 또는 미지정)
7. **팀원별 부하 바**: 팀원마다 진행 중인 카드 수를 표시하고, 클릭하면 그 사람 카드만 보이게 필터링

## 5. 데이터 모델 (Supabase 테이블)
| 테이블 | 컬럼 | 비고 |
|---|---|---|
| teams | id, name, created_at | 보드 역할을 겸함 |
| members | id, team_id, name, color | 팀마다 따로 등록. 로그인 계정과 연결하지 않음 (가정) |
| columns | id, team_id, title, position, is_done | is_done 컬럼에 있는 카드는 부하 계산에서 제외 (가정) |
| cards | id, column_id, title, description, assignee_id (null 허용), position, created_at | |

- 외래키 삭제 규칙: 팀을 지우면 그 팀의 members, columns, cards가 함께 삭제됨 (cascade). 담당자 팀원이 삭제되면 카드의 assignee_id는 null이 됨
- RLS 정책: 4개 테이블 모두 `anon`과 `authenticated` 역할에 대해 select, insert, update, delete를 `using (true) with check (true)`로 허용

## 6. 차별점 (1개)
> 팀원별 진행 중인 카드 수(부하)가 보드 상단에 항상 보이고, 누르면 그 사람의 카드만 걸러서 보여준다.

## 7. 범위 제외 (Out of Scope)
- 실시간 반영(Supabase Realtime). 다른 사람의 변경은 새로고침하거나 창에 다시 포커스할 때 다시 불러와서 반영 (가정)
- 팀별 접근 권한, 초대, 역할 구분
- 소셜 로그인, 비밀번호 재설정 화면
- 댓글, 첨부파일, 알림, 활동 이력, 라벨, 마감일, 체크리스트
- 한 카드에 담당자 여러 명

## 8. 완료 기준 (Definition of Done)
- 이메일로 가입하고 로그인할 수 있으며, 로그아웃하면 로그인 화면으로 돌아간다
- 팀 2개 이상을 만들어 전환할 수 있고, 팀마다 보드가 독립적으로 유지된다
- 카드를 드래그해 옮기면 부하 바의 숫자가 즉시 바뀌고, 새로고침해도 변경이 유지된다
- 다른 브라우저에서 다른 계정으로 로그인해도 같은 데이터가 보인다
- 부하 바에서 팀원을 클릭하면 그 사람 카드만 보이고, 다시 클릭하면 필터가 풀린다
- `npm run build`가 오류 없이 통과한다

## 알려진 위험
- anon 전체 허용 정책이라 **로그인은 화면 진입을 막는 역할만 한다.** 프론트엔드에 들어가는 anon key만 있으면 누구나 API로 데이터를 직접 읽고 쓸 수 있다. 사내 테스트 용도로만 쓰고, 외부에 공개하기 전에 authenticated 전용 정책으로 바꿔야 한다
- 반나절 예산에 Supabase 설정과 로그인이 추가되어 일정이 빠듯하다. 시간이 모자라면 컬럼 순서 변경을 v2로 미룬다

## 가정 목록
- 목적은 팀 내부 도구, 디바이스는 데스크톱 우선
- 스택은 React + TS + Vite + @dnd-kit + supabase-js
- 이메일 로그인은 이메일 + 비밀번호 방식 (매직 링크가 아님)
- 팀원(members)은 로그인 계정과 연결하지 않고 이름으로만 관리
- 실시간 반영은 하지 않고, 창에 다시 포커스할 때 데이터를 다시 불러옴
- "진행 중"의 정의: 완료(is_done) 컬럼이 아닌 모든 컬럼에 있는 카드
- 담당자는 카드당 1명
- 첫 로그인 시 데이터가 비어 있으면 예시 팀 1개를 만들어둠
